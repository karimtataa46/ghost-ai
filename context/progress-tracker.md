## Architecture Decisions

- Auth is Clerk (`@clerk/nextjs`). Provider lives in `app/layout.tsx` inside `<body>`; middleware is `proxy.ts` (Next.js 16). Never expose `CLERK_SECRET_KEY` client-side; do not read or print `.env.local`.
- Routes are protected by default in `proxy.ts`; only the sign-in/sign-up paths from the existing Clerk env vars are public. Those env vars are constrained to `/sign-in` and `/sign-up` (the only auth routes that exist; verified the configured values match). A review suggested adding `/login` and `/register` pages for non-default values; skipped because those paths are invented and a static route cannot cover arbitrary values. To use different URLs, add matching `app/` pages first. `cacheComponents` is on, so anything calling `auth()` or rendering Clerk client components that read the path must sit inside `<Suspense>`.

- `ProjectSidebar` is `absolute` and must be placed inside a `relative` container below the navbar; `EditorShell` owns the `isOpen` state. Its scrim is a sibling of the `aside` in the same container, so it needs that container too.
- `EditorShell` is mounted in `app/editor/layout.tsx`, so only `/editor` routes get the editor chrome; auth pages use `AuthLayout` instead. It wraps everything in `ProjectsProvider`, so any component under `/editor` can call `useProjects()` to read the project list and open the project dialogs; the dialogs themselves render once, in the provider.
- Dialog pattern is a wrapper (`DialogShell`) over unmodified `components/ui/dialog.tsx`; the shadcn overlay stays default since `components/ui/*` is protected.

- shadcn style is `base-nova` (Base UI primitives, not Radix); triggers use a `render` prop instead of `asChild`.
- Dark only: `<html class="dark">`, tokens defined on `:root` in `globals.css`; shadcn semantic vars (`--background`, `--primary`, `--border`, ...) alias the project tokens.

## Session Notes

- Layout metadata title is still the create-next-app default.
- Browser checks in the Chrome tool run in a tab with `document.visibilityState === "hidden"`: CSS transitions and Base UI exit animations never advance, so closed dialogs stay mounted as `data-closed` and the sidebar stays visually closed. Inject `*{transition:none !important;animation:none !important}` to see end states, reload between dialog checks, and expect the first click after a navigation, and the first keystrokes right after a dialog opens, to be dropped (Base UI moves focus into the dialog late in a hidden tab; wait for hydration/focus, check `document.activeElement`, then repeat).
- Clerk's dev session cookie is shared across `localhost` ports, so a browser already signed in on `localhost:3000` is also signed in on any other `localhost` port. Use `127.0.0.1` to see the signed-out state without signing out.
- Resizing the browser window through the Chrome tool does not change the page viewport. To check small-screen layouts, load the route in a narrow same-origin `<iframe>` (media queries evaluate against the iframe width) and measure from its `contentDocument`.
- `next dev` rewrites the tracked `AGENTS.md` (Next.js agent-rules and agent-feedback blocks) on start. It was restored after the browser check; expect that diff to reappear whenever the dev server runs.
