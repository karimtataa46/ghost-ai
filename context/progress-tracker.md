## Architecture Decisions

- Auth is Clerk (`@clerk/nextjs`). Provider lives in `app/layout.tsx` inside `<body>`; middleware is `proxy.ts` (Next.js 16). Never expose `CLERK_SECRET_KEY` client-side; do not read or print `.env.local`.
- Routes are protected by default in `proxy.ts`; only the sign-in/sign-up paths from the existing Clerk env vars are public. Those env vars are constrained to `/sign-in` and `/sign-up` (the only auth routes that exist; verified the configured values match). A review suggested adding `/login` and `/register` pages for non-default values; skipped because those paths are invented and a static route cannot cover arbitrary values. To use different URLs, add matching `app/` pages first. `cacheComponents` is on, so anything calling `auth()` or rendering Clerk client components that read the path must sit inside `<Suspense>`.

- `ProjectSidebar` is `absolute` and must be placed inside a `relative` container below the navbar; `EditorShell` owns the `isOpen` state. Its scrim is a sibling of the `aside` in the same container, so it needs that container too.
- `app/editor/layout.tsx` mounts `ProjectsProvider` (not a shell), so any component under `/editor` can call `useProjects()` to read the owned and shared lists and open the project dialogs; the dialogs render once, in the provider. Each page renders its own chrome: `EditorShell` (home and `AccessDenied`) or `WorkspaceShell` (an open project, with `project` from the page's access check). Auth pages use `AuthLayout` instead. The lists are server props from the layout (not client state), so a mutation must be followed by `router.refresh()` to update the sidebar; `useProjectActions` does this.
- Identity and project access checks live in `lib/project-access.ts` (`getCurrentUser`, `findAccessibleProject`); pages and future token routes use them rather than querying access inline.
- A project's ID is its Liveblocks room ID. The client builds it (`createRoomId`) and `POST /api/projects` stores it as the primary key.
- Dialog pattern is a wrapper (`DialogShell`) over unmodified `components/ui/dialog.tsx`; the shadcn overlay stays default since `components/ui/*` is protected.

- shadcn style is `base-nova` (Base UI primitives, not Radix); triggers use a `render` prop instead of `asChild`.
- Dark only: `<html class="dark">`, tokens defined on `:root` in `globals.css`; shadcn semantic vars (`--background`, `--primary`, `--border`, ...) alias the project tokens.

## Session Notes

- Layout metadata title is still the create-next-app default.
- Browser checks in the Chrome tool run in a tab with `document.visibilityState === "hidden"`: CSS transitions and Base UI exit animations never advance, so closed dialogs stay mounted as `data-closed` and the sidebar stays visually closed. Inject `*{transition:none !important;animation:none !important}` to see end states, reload between dialog checks, and expect the first click after a navigation, and the first keystrokes right after a dialog opens, to be dropped (Base UI moves focus into the dialog late in a hidden tab; wait for hydration/focus, check `document.activeElement`, then repeat).
- Clerk's dev session cookie is shared across `localhost` ports, so a browser already signed in on `localhost:3000` is also signed in on any other `localhost` port. Use `127.0.0.1` to see the signed-out state without signing out.
- Resizing the browser window through the Chrome tool does not change the page viewport. To check small-screen layouts, load the route in a narrow same-origin `<iframe>` (media queries evaluate against the iframe width) and measure from its `contentDocument`.
- `next dev` rewrites the tracked `AGENTS.md` (Next.js agent-rules and agent-feedback blocks) on start. It was restored after the browser check; expect that diff to reappear whenever the dev server runs.
- On a fresh page load in the hidden Chrome tab, the DOM can briefly hold two copies of the Suspense-streamed editor shell (two asides, doubled sidebar items) until React swaps the streamed content in; re-query after a couple of seconds before judging. `router.push` / `router.refresh()` results also take several seconds to appear in that tab.
- `next dev` writes generated route types to `.next/dev/types`, which `tsc` and `next build` include. If a route that was served in dev is then deleted (a temporary preview page), the build fails with `TS2307` on the deleted `page.js`. Fix: `rm -rf .next/dev` (gitignored cache, regenerated by `next dev`).
- The Chrome `javascript_tool` returned `{}` for an async `fetch(...)` expression in this setup (create and delete of a test project both did), so it cannot confirm an API result; check the dev server log or the database instead. `read_network_requests` only tracks from its first call, so it misses requests from a page that loaded earlier; the dev server log shows route calls too.
- `next dev` refuses a second instance for the same directory ("Another next dev server is already running"), so if the user already has one on port 3000, test against that one; it hot-reloads a temporary route within a second, and it does not rewrite `AGENTS.md` again. Do not `rm -rf .next/dev` while it is running.
- In the Chrome tool, `left_click_drag` performs a real HTML5 drag and drop (dragstart, dragover, drop with a real `DataTransfer`), so drag-and-drop UI can be tested with it directly. Its screenshot frame is 1456 px wide while the page viewport is 1728 px, so coordinates given to the tool are scaled by about 1.187 in page pixels. The `scroll` action does not zoom a React Flow canvas (not even with `ctrl`); dispatching `new WheelEvent("wheel", { deltaY: -120, ctrlKey: true, clientX, clientY, bubbles: true, cancelable: true })` on `.react-flow__renderer` does. Dragging empty pane space pans it.
- Testing mutations in the browser writes to the real database in `.env`: use clearly named projects (`Verify ...`) and delete them through the UI, then confirm the table is empty with a short `tsx` script (`node --env-file=.env --import tsx <script>`; `dotenv` is not importable from outside the project).
